# eVTOL 高度制御 制御設計書

**Document ID:** EVTOL-CTRL-001  
**Version:** 1.0  
**対象システム:** AutonomousMobileDrone V1.0  
**対応仕様:** EVTOL-SPEC-001 第7章・第8章・第11章  
**実装:** `src/controller`, `src/dynamics`, `simulation/simulator.py`

---

## 1. 目的

本設計書は、V1.0 の鉛直方向高度制御について、制御則・機体パラメータ・制限・期待性能を固定する。

対象はシミュレーション上の点質量モデルに限る。姿勢制御・6DOF・実機推力配分は対象外とする。

---

## 2. 制御対象

### 2.1 運動方程式

鉛直上向きを正とする。

```text
m * a = T - m g - Fd
```

| 記号 | 意味 | V1.0 値 |
|------|------|---------|
| \(m\) | 機体質量 | 10.0 kg |
| \(g\) | 重力加速度 | 9.81 m/s² |
| \(T\) | 推力指令 | 0 ≤ T ≤ 250 N |
| \(Fd\) | 外乱（上向き正の抗力相当。実装では下向き外乱を正の \(Fd\) として減算） | シナリオ入力 |
| \(a\) | 鉛直加速度 | 状態量 |

ホバリング推力:

```text
T_hover = m g = 98.1 N
```

最大余剰推力による上昇加速度:

```text
a_max = (T_max - T_hover) / m = (250 - 98.1) / 10 = 15.19 m/s²
```

推力ゼロ時の下降加速度は \(g\) に近い（地面接触時は高度・下降速度を 0 に拘束）。

### 2.2 センサ

V1.0 の高度センサは真値を返す（ノイズ標準偏差 0）。制御器はセンサ出力のみを用いる。

---

## 3. 制御アーキテクチャ

仕様 7.2 に、ホバリング推力のフィードフォワードを追加する。誤差ゼロで推力が \(mg\) になるため、積分器だけにホバー推力を担わせない。

```text
Target Altitude  z_cmd
       │
       ↓
 ┌──────────────┐
 │ Error        │  e = z_cmd - z_meas
 └──────┬───────┘
        ↓
 ┌──────────────┐
 │ PID          │  u = Kp e + Ki ∫e dt + Kd de/dt
 └──────┬───────┘
        ↓
 ┌──────────────┐
 │ + T_hover    │  T* = T_hover + u
 └──────┬───────┘
        ↓
 ┌──────────────┐
 │ Thrust Limit │  T = clip(T*, 0, T_max)
 └──────┬───────┘
        ↓
   eVTOL Dynamics
        ↓
   z, v  → Sensor → Feedback
```

制御周期: **10 ms**（100 Hz）。離散化は前進オイラー。

実装対応:

- 誤差・PID: `PidController`（C++）
- フィードフォワードと最終クリップ: `AltitudeController`（Python）
- PID 出力の上下限: \([-T_{hover},\; T_{max}-T_{hover}]\) = \([-98.1,\; 151.9]\) N  
  これにより \(T\) は必ず \([0,\; 250]\) N に収まる（REQ-F-005）。

---

## 4. 制御則

### 4.1 誤差（REQ-F-003）

```text
e(t) = z_cmd(t) - z_meas(t)
```

単位は m。

### 4.2 PID（REQ-F-004）

連続時間:

```text
u(t) = Kp e(t) + Ki ∫ e(τ) dτ + Kd de(t)/dt
```

離散時間（制御周期 \(\Delta t = 0.01\) s）:

```text
P = Kp * e[k]
I[k] = I[k-1] + e[k] * Δt     （飽和時は後述の条件で凍結）
D = Kd * (e[k] - e[k-1]) / Δt   （初回サンプルは D = 0）
u[k] = clip(P + Ki*I[k] + D, u_min, u_max)
```

目標高度が一定のとき \(de/dt \approx -v\) であり、D 項は速度ダンピングとして働く。

### 4.3 ゲイン（V1.0 採用値）

| ゲイン | 値 | 単位 | 役割 |
|--------|-----|------|------|
| \(K_p\) | 4.0 | N/m | 高度誤差に比例した推力補正 |
| \(K_i\) | 0.45 | N/(m·s) | 定常偏差の除去 |
| \(K_d\) | 16.0 | N/(m/s) | 上昇・下降速度の減衰 |

線形化（飽和なし・\(Fd=0\)・I 項無視）では:

```text
ωn = sqrt(Kp / m) = sqrt(0.40) ≈ 0.63 rad/s
ζ  = Kd / (2 m ωn) ≈ 1.27
```

つまり線形領域では過減衰に近い。実際の 0→100 m は推力上限に張り付くため、この二次系近似は初期上昇には使えない。

### 4.4 アンチワインドアップ

出力が上限に張り、かつ \(e > 0\) のとき積分を更新しない。下限に張り、かつ \(e < 0\) のときも同様。

大誤差の離陸・降下で積分が飽和し続け、目標到達後に過大な推力が残るのを防ぐ。

---

## 5. ゲイン選定の根拠

1. **P:** \(K_p=4\) は線形領域で \(\omega_n \approx 0.63\) rad/s。ホバー近傍のゆるい復元力。100 m 級のステップではすぐ \(T=T_{max}\) になる。
2. **D:** \(K_d=16\) は 10 m/s の上昇に対し約 160 N の減速推力。\(K_d\) を過大にすると D が負側に飽和し推力が 0 になり、大きなバウンドを起こす（試行で確認）。
3. **I:** \(K_i=0.45\) はモデル化誤差と外乱後のオフセットを数十秒で消す。ホバー推力 FF があるため I の負担は小さい。

V1.0 は「到達・復帰・試験成立」を優先した。オーバーシュート最小化は次の設計イテレーションとする。

## 6. 飛行状態判定（制御出力ではない）

状態推定は推力計算に使わない。監視・ログ用（REQ-F-009）。

| 状態 | 主な条件（実装閾値） |
|------|----------------------|
| GROUND | 高度 ≤ 0.2 m かつ \|速度\| ≤ 0.15 m/s |
| TAKEOFF | 地上離脱後、高度 < 8 m かつ上昇 |
| CLIMB | 上昇速度 ≥ 0.6 m/s |
| HOVER | \|誤差\| ≤ 3 m かつ \|速度\| ≤ 0.5 m/s |
| DESCEND | 下降速度 ≤ −0.6 m/s |
| LANDING | 高度 ≤ 5 m、下降、目標も低高度 |

## 8. 既知の制限と次設計

1. **大ステップ応答のオーバーシュート（約 20%）**  
   対策候補: 目標高度のランプ / 速度指令の内ループ / 推力余裕を残す接近則。
2. **降下時のアンダーシュート**  
   推力下限 0 により自由落下に近くなる区間がある。
3. **センサノイズ・遅延なし**  
   Phase 3 でノイズを入れると D 項の増幅が問題になる。そのとき微分フィルタが必要。
4. **1 自由度のみ**  
   姿勢・水平位置は V2.0 以降。
